# 網頁網站登入、使用者額度與 ZIP

使用者補充要求：網站要求登入時，在下載工具中按該網站登入，手動登入後取得 cookies；增加管理者與一般帳號、每日預設與個別額度；一鍵將完成項目包為 ZIP。

已確認預設：一般使用者每天 5 部，可由管理者在網頁調整；管理者不限部數。額度計算成功影片，排隊先保留，失敗或刪除排隊任務歸還。以 Asia/Taipei 日期計算，成功紀錄存 SQLite，登出、刪除完成任務或重啟不清除。跨日未完成預留繼續保留，完成時計入完成當天。

方案：沿用 FastAPI/Vue。新增 SQLite 帳號與額度帳本、scrypt 密碼與管理 API；現有 Token 為系統管理者，首次 OIDC 登入預設一般使用者，OIDC_ADMIN_SUBJECTS 可指定初始 SSO 管理者。API、WebSocket、單檔、ZIP、cookies 皆依使用者隔離。

登入採伺服器 Chromium 獨立 browser context，使用者透過工具內的遠端畫面自行操作登入與驗證，完成後擷取目標網站 cookies，使用由 session secret 衍生的金鑰加密保存於個人資料。解析與下載依網站自動選用個人 cookies。一般 popup 或 OAuth 不提供此能力；Google 等網站可能拒絕受自動化控制的瀏覽器，保留個人 cookies.txt 匯入，不聲稱可通過所有網站的限制。瀏覽器不保留密碼、錄影或持久 profile。

視窗限每人一個，預設最多四個、最長二十分鐘；網站導航限目標與指定登入網域，拒絕私有網路。網站登入受各站登入與驗證機制限制，硬體 passkey、被拒絕的自動化瀏覽器不保證可用。

ZIP 使用 zipstream-ng + ZIP_STORED 串流，支援 Zip64，避免另存整份 ZIP 或在瀏覽器以 Blob 累積全部影片。完成項目依個人篩選，檔名移除路徑與控制字元、重名自動編號；串流期間避免清理或刪除檔案。不重複扣下載額度。

測試：額度原子性、個別與全體設定、管理者不限、跨日、失敗歸還、重啟與刪除不重置、角色/停用即時生效、帳號/網站 cookies/WS/檔案隔離、ZIP 重名與內容、真實瀏覽器在本地登入頁的操作與 cookies 擷取/自動下載。
